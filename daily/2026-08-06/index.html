🪤 Break the Filter

A hands-on sandbox for the "framework is the vulnerability" story — no LLM required, just you vs. a leaky guardrail.

Companion to today's post on AI agent framework exploitation (Black Hat USA, Aug 5 2026) · runs entirely in your browser, nothing you type leaves this page

The setup

An AI search agent lets a model fill in a city parameter. The framework builds a filter function by pasting that value straight into a Python string, then hands it to an "AST-guarded" evaluator meant to stop dangerous code:

lambda x: x.city == '{your input}'

This is a simplified, client-side re-creation of the real bug behind CVE-2026-26030, disclosed in Microsoft's Semantic Kernel. Nothing here executes real code — the "guard" below is a JavaScript stand-in for the actual AST blocklist, reproducing the same category of gaps. Your job: think like the model would if an attacker had hijacked its instructions, and get past three levels of the guard.

What actually fixes this

Once you've cleared all three levels, the pattern behind them is worth naming: the guard was a blocklist (deny known-bad tokens) protecting something that should never have accepted arbitrary code in the first place.

Vulnerable pattern

filter_fn = eval(f"lambda x: x.city == '{user_city}'")
# blocklist checks for 'import', 'exec', 'os.', etc — but
# never inspects attribute-chain or subscript AST nodes

Fixed pattern

from dataclasses import dataclass

@dataclass
class CityFilter:
    city: str

def apply_filter(records, f: CityFilter):
    return [r for r in records if r.city == f.city]
# no eval, no string-built code — user input is DATA,
# never assembled into anything the interpreter parses as code

The fix isn't a better blocklist. It's removing eval() from the path a model-controlled string can reach at all — swap dynamic code construction for a structured, typed filter object. If you must accept dynamic expressions, use an allowlist of AST node types (e.g. only Compare, Name, Constant) rather than a denylist of scary words, since attribute traversal (__class__, __base__, __subclasses__) and subscript access ([...]) route around word-based filters every time.
